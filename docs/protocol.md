# Протокол первого эксперимента

## Исследовательский вопрос

Помогает ли объединение оценок Bwen-8B и EvaByte решать небольшие задачи чтения
якутского текста лучше, чем Qwen3-8B-Base после языковой адаптации?

Это сравнение конкретных систем. Оно не доказывает превосходство байтовой
архитектуры: модели отличаются исходными корпусами, вычислительным бюджетом,
размером и количеством моделей при ответе. Две модели требуют дополнительных
вычислений. Учитывайте качество вместе со временем и стоимостью.

## Системы

1. Qwen3-8B-Base без адаптации — исходный контроль.
2. Qwen3-8B-Base + LoRA на якутском — основной контроль после адаптации.
3. Bwen-8B отдельно — проверка вклада первого участника.
4. EvaByte отдельно — проверка вклада второго участника.
5. Bwen-8B + EvaByte — геометрическое объединение распределений A–D.

На первом этапе байтовые модели используются как опубликованы. Если позднее
адаптировать их тоже, это отдельный эксперимент с явным бюджетом обучения.
Код адаптации Bwen/EvaByte в эту версию не входит: upstream Bwen forward отличается
от стандартного causal-LM Trainer и требует отдельной реализации функции потерь.

## Оценка

Вход: якутский контекст, русский вопрос, 2–4 варианта ответа. В исходном пилоте
варианты русские; в задаче UD это якутские леммы. Такой протокол проверяет
понимание якутского при русскоязычной постановке задачи. Генерация грамотного
якутского текста, разговор, длинное рассуждение и перевод этим тестом не измеряются.

Один forward pass получает только промпт, заканчивающийся `Ответ: `.
Ни правильная буква, ни текст продолжения в модель не подаются. Берутся оценки
следующего атома для первых N букв из A, B, C, D и нормализуются только между
существующими N ответами. SAAS и классификация типа сущности имеют три ответа.
В каждом токенизаторе проверяется, что отдельная буква кодируется одним атомом.
Это стандартизованный выбор ответа, а не вероятность полного русского ответа.

- Bwen: до нормализации суммируются вероятности буквы без границы и с fused boundary.
  В текущем чекпойнте выход 520, две половины по 260, включая специальные атомы.
- EvaByte: используется только первая голова next-byte; batch=1, без padding mask.
- Qwen: обычные next-token logits. Не используется instruct/chat checkpoint.
- Все системы работают в BF16, без квантизации и без автоматической обрезки.

Каждый вариант занимает каждую позицию за N циклических перестановок.
Средние log probabilities возвращаются к исходному порядку вариантов. Это уменьшает
позиционное предпочтение, но не устраняет все эффекты порядка.
Русский контроль разрешён только при наличии проверенного `context_ru`;
конвертеры не генерируют переводов. Равенство максимальных оценок разрешается в пользу первого варианта и отмечается
полем `tied`; при заметном числе равенств протокол нужно пересмотреть.

Ансамбль: `s_i = 0.5 * mean_log_p_Bwen(i) + 0.5 * mean_log_p_EvaByte(i)`.
Ответ — индекс максимального `s_i`. Это объединение на уровне ответов, а не весов,
байтовых словарей или свободно сгенерированных текстов.

## Пилот и проверка

Генератор содержит 16 оригинальных AI-черновиков: роли, отрицание, количество,
время, принадлежность, признаки, местонахождение, местоимения. Все `draft`.
Пары меняют одну значимую часть текста; они не обязательно являются строгими
лингвистическими минимальными парами. Эти задания технически проверяют тракт,
но слишком малы и просты для заключения об общем понимании якутского.

Для каждого задания носитель должен подтвердить:

1. Естественность и правильность якутского текста и его перевода.
2. Единственный верный ответ, выводимый из контекста.
3. Отсутствие подсказки только в вопросе или необычной длине ответа.
4. Корректность объяснения и полезность категории.
5. Сохранение значимого отличия между двумя заданиями пары.

После проверки: `review_status = approved`, `reviewer = идентификатор проверяющего`.
При изменении файла теста его SHA меняется: старые результаты нельзя объединять
с новыми. Разметка не должна исправляться задним числом только потому, что модель
дала неудобный результат.

Отчёт содержит accuracy, результаты категорий и интервал Уилсона. На 16 связанных
заданиях интервал служит описательным ориентиром; пары не независимы, поэтому
интервал не является строгим доказательством преимущества. Для исследования
потребуется расширить тест и оценивать разницу систем с учётом групп/пар.

Параметр ансамбля выбирается на отдельном dev-наборе. Пилот следует отделить от
итогового закрытого теста. Для обучения морфологии в дальнейшем нужен тест на
новых основах и парадигмах, а не только случайное разбиение словоформ.

## Отложенная серверная верификация

На устройстве пользователя ничего не запускать. На арендованной ВМ проверить:

- unit-тесты протокола;
- загрузку каждого tokenizer/model из закреплённой ревизии;
- форму, конечность и повторяемость logits на одном задании;
- корректность перенаправления вложенного токенизатора Bwen;
- суммирование двух половин выхода Bwen и выбор первой головы EvaByte;
- прогон на одном задании, затем на 16, с сохранением ошибок и версий;
- простой тренировочный шаг Qwen до полного пилотного дообучения.

Первые оценки времени включают прогрев; это не чистый throughput-бенчмарк.
Совместная оценка двух участников требует суммы их затрат, даже если их результаты
агрегируются позже. Раздельные окружения позволяют использовать одну GPU.
