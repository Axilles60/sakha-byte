# IMMERS CLOUD: план удалённого размещения

Публичные страницы изучены 16 ноября 2026 года. Ресурсы не арендованы,
авторизация в аккаунте не выполнялась, ключи не получены. Наличие свободной GPU,
квоты и итоговая цена в кабинете пока не проверены.

## Подходящий сервис

Для исследования выбираем обычную GPU-ВМ Linux с SSH. У нас собственные
Transformers-адаптеры с нестандартными байтовыми моделями, а не только вызовы
chat/completions. Установка обычной ВМ не зависит от наличия Bwen/EvaByte в
каталоге готовых эндпоинтов.

IMMERS предлагает GPU-ВМ, SSH для Linux и OpenStack API Zed. На странице API
предлагается обратиться в поддержку за доступом. Там же перечислены Compute,
Identity, Images, Networking, Block Storage и собственный API кабинета.
Не следует считать токен chat.immers.cloud ключом инфраструктурного OpenStack API.

Источники: [GPU](https://immers.cloud/gpu/), [API](https://immers.cloud/api/),
[FAQ](https://immers.cloud/faq/).

## Выбор оборудования

Для первого технического запуска рекомендую **1×A100 80GB, 64GB RAM, 240GB диск,
Ubuntu 24.04**. Это инженерная рекомендация с запасом для BF16, окружений и
Qwen LoRA; фактическую память и скорость ещё нужно измерить. Модели можно
оценивать последовательно на одной GPU и объединять оценки позднее.

Публичные примеры цен на дату исследования:

| `rtx5090-1.8.64.160` | 8 vCPU / 64GB / 160GB | 137,37 ₽ |
| `teslaa100-1.16.64.240` | 16 vCPU / 64GB / 240GB | 212,54 ₽ |

Источники: [RTX 4090](https://immers.cloud/gpu/4090/),
[RTX 5090](https://immers.cloud/gpu/5090/), [A100](https://immers.cloud/gpu/a100/).
Это опубликованные примеры, не подтверждение доступности или итоговой цены заказа.
Оценка 2 часов на выбранном A100 — 425,08 ₽, 4 часов — 850,16 ₽ только по
указанному часовому тарифу. Это лимиты-планирование, не прогноз длительности.
Хранение, IP и изменение конфигурации могут менять стоимость.

RTX 4090 может быть экономичным вариантом для последовательного инференса с
коротким контекстом, но запас памяти меньше. RTX 5090 требует проверки поддержки
нового GPU в PyTorch/Triton; предложенное старое окружение EvaByte для неё не
считается готовым. Именно поэтому первый запуск предложен на A100.

## Доступ и жизненный цикл

Для SSH достаточно адреса/порта, имени пользователя, механизма ключа и
подтверждения fingerprint сервера. Для первичной работы по уже созданной ВМ
инфраструктурный API необязателен. Для автоматизации понадобятся реквизиты
OpenStack проекта и права на нужные операции; их точный формат уточняется в
аккаунте/поддержке. Идентификаторы image/flavor/network/security group определяются
из доступных ресурсов аккаунта, не копируются из примеров документации.

Секреты не включать в репозиторий или конфигурации проекта. Использовать внешнее
хранилище секретов/SSH agent и отдельные права доступа. Веса, датасеты и выполнение
эксперимента остаются на IMMERS. Копируйте результаты, журналы и манифесты на
компьютер пользователя после каждого завершённого этапа.

У провайдера есть готовые OpenAI-совместимые эндпоинты и отдельные токены для них;
это не замена SSH для этого проекта и не гарантия поддержки Bwen/EvaByte в vLLM.

**Stop не прекращает все начисления:** по FAQ остаются диски, IP и зарезервированные
PCIe-устройства GPU. **Shelve** освобождает вычислительные ресурсы; сохраняется
оплата хранения снимка/тома и IP. Переход и начисления нужно проверить в кабинете.
Автоматическое удаление в этом проекте не включено, поскольку оно уничтожает ВМ.
Сначала сохраняются результаты на удалённом постоянном томе/объектном хранилище.

Источник: [FAQ, архивация и тарификация](https://immers.cloud/faq/).

## Следующий удалённый этап

1. Получить параметры существующей ВМ либо определить конкретную конфигурацию и бюджет заказа.
2. Проверить права, GPU, драйвер, диск и исходящий доступ к Hugging Face/GitHub.
3. Разместить только исходники проекта на ВМ, установить изолированные окружения.
4. Сначала запустить unit-тесты и одно задание на каждой модели.
5. После технической проверки выполнить пилот и ансамбль.
6. Для Qwen LoRA отдельно получить допустимый корпус на якутском и его разбиение.
7. Проверить локальные копии результатов и журналов, затем выполнить согласованный Shelve.

Создание платных ресурсов, удаление ВМ и расходование бюджета этим файлом
не выполняются. `configs/immers.example.yaml` содержит только шаблон намерений,
без секретов и без действующих реквизитов.
